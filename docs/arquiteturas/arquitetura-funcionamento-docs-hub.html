Visão Geral

O que é o SRE Documentation Hub

Guia resumido para todo o time entender como nossas documentações HTML são organizadas, indexadas e publicadas no GitHub Pages.

Um portal único, sem manutenção manual de catálogo

O SRE Documentation Hub centraliza relatórios executivos, arquiteturas, runbooks, procedimentos e apresentações da equipe de SRE Captura Física e Digital. Basta adicionar um arquivo .html na pasta certa do repositório: a pipeline descobre o arquivo, extrai o conteúdo para busca e atualiza o site sozinha.

Como seria sem automação

  • Editar manualmente o index.html a cada nova doc
  • Conflitos de merge em listas de links e datas
  • Busca limitada apenas ao título do card
  • Risco de expor scripts e automações do repositório
➜

Como funciona no nosso Hub

  • Basta commitar o .html na pasta da categoria
  • Data extraída automaticamente do commit no Git
  • Busca full-text lê todo o conteúdo interno do HTML
  • Apenas a pasta ./docs vai para o GitHub Pages
Isolamento de segurançaMesmo que o repositório contenha as pastas agents/, automations/, scripts/ e monitoring/, o artefato enviado ao GitHub Pages empacota exclusivamente a pasta ./docs.
Fluxo do Time

Como publicar um novo documento

Qualquer pessoa do time publica uma nova documentação em 2 passos simples, sem tocar no código do portal.

Onde salvar cada tipo de arquivo

Pasta no RepositórioAba no HubO que colocar aqui
docs/arquiteturas/ArquiteturasDesenhos de malha transacional (POS/TEF, Pix, 3DS), topologias AKS e fluxos de referência.
docs/runbooks/RunbooksGuias rápidos de ação para plantão e mitigação de incidentes (OOMKill, lag Kafka, contingência).
docs/procedimentos/ProcedimentosPOPs planejados: onboarding no Dynatrace, rotação de certificados mTLS, checklist de Black Friday.
docs/relatorios/RelatóriosRelatórios executivos e técnicos com dados reais (ex: Recapacity Split, pós-Black Friday, análises).
docs/apresentacoes/ApresentaçõesDecks de slides em HTML para reuniões de governança, SLOs e post-mortems executivos.

Passo a passo no Git

Depois de criar seu arquivo .html (manualmente ou gerado por IA seguindo nosso tema Dark), basta commitar e enviar para a branch main:

git add docs/relatorios/meu-novo-relatorio.html
git commit -m "docs(relatorios): adiciona relatorio de capacidade"
git push origin main
E se eu commitar 10 documentos de uma vez?Pode commitar quantos arquivos quiser no mesmo push. O script varre todas as pastas em milissegundos e publica todos os documentos juntos na mesma execução.
CI/CD Pipeline

Como funciona o GitHub Actions

O arquivo .github/workflows/deploy-pages.yml utiliza o modelo oficial Static HTML (By GitHub Actions) com um passo de indexação Python antes do deploy.

As 5 etapas da nossa Pipeline

EtapaAction / ComandoPor que ela existe
1. Checkout completoactions/checkout@v4 (fetch-depth: 0)Baixa o repositório com todo o histórico de commits para sabermos a data exata de cada doc.
2. Ambiente Pythonactions/setup-python@v5 (Python 3.12)Prepara o Python nativo na máquina virtual do GitHub Actions (sem dependências externas).
3. Indexação automáticapython docs/generate_index.pyLê todos os HTMLs de docs/ e gera o catálogo docs/docs.json atualizado em tempo de build.
4. Empacotamento isoladoactions/upload-pages-artifact@v3Empacota apenas path: './docs' como artefato estático (com .nojekyll).
5. Publicaçãoactions/deploy-pages@v4Publica o artefato no GitHub Pages e disponibiliza a URL atualizada em ~20 segundos.
Controle de Concorrência (Fila)A opção concurrency: group: "pages" garante que se duas pessoas derem push ao mesmo tempo, o segundo deploy aguarda o primeiro terminar sem sobrescrever nada.
Execução Manual (Workflow Dispatch)Além de rodar a cada push na main, qualquer membro pode disparar manualmente o botão Run workflow na aba Actions do GitHub.
Motor de Indexação

Como funciona o Script Python (generate_index.py)

Escrito apenas com bibliotecas nativas do Python (html.parser, pathlib, subprocess, json, re) para rodar rápido e nunca quebrar por falta de pacotes.

O que o script extrai de cada HTML

Campo no docs.jsonDe onde o Python extraiFallback (se não existir no HTML)
titleTag <title> ou primeiro <h1> da páginaNome do arquivo formatado (ex: meu-runbook.html → Meu Runbook).
descriptionTag <meta name="description">Texto do primeiro parágrafo <p> visível do documento.
categoryNome da subpasta onde o arquivo está salvoClassificado automaticamente pela pasta (relatorios, runbooks, etc.).
updated_atComando git log -1 --format=%cs -- arquivo.htmlData de modificação do arquivo no sistema (mtime) em testes locais.
search_textTodo o texto útil do corpo (títulos, tabelas, códigos kubectl)Ignora <style> e <script> e remove palavras duplicadas.
Por que a data vem do Git?Ao usar git log -1 --format=%cs, a data exibida no card do Hub reflete sempre o último commit real que alterou aquele documento, sem ninguém precisar lembrar de atualizar datas dentro do HTML.
Experiência de Uso

Busca Full-Text e Ordenação no Portal

O arquivo docs/index.html consome o ./docs.json gerado pela Action e monta a interface limpa do Hub no navegador.

Busca Full-Text (Sem poluir os cards)Graças ao campo search_text gerado pelo Python, você pode pesquisar por qualquer comando (kubectl), nome de serviço (split-api, pos-worker), cluster (aks-split-brs-prd) ou sigla (ISO-8583, OOMKill) que esteja dentro do documento — mantendo o visual dos cards limpo e sem dezenas de tags penduradas.
Normalização de Acentos e Multi-TermosA busca no navegador remove acentos automaticamente (buscar por conciliacao encontra Conciliação) e aceita múltiplas palavras ao mesmo tempo (ex: aks split oomkill).
Ordenação por Data e AlfabetoO seletor customizado permite alternar instantaneamente entre Mais recentes primeiro, Mais antigos primeiro, Título (A–Z) e Título (Z–A).
Atalho Rápido de TecladoPressionar a tecla / em qualquer lugar do Hub leva o cursor direto para a barra de pesquisa.
