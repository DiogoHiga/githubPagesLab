Onboarding de Clusters AKS e Workloads no Dynatrace

Guia padronizado para implantação do Dynatrace Operator (DynaKube) em modo cloudNativeFullStack, taxonomia obrigatória de labels Kubernetes e ativação de alertas de anomalia (CPU Throttling, OOMKill e SLOs).

1. Pré-requisitos e Criação de Tokens na Tenant Dynatrace

Gere os tokens no cofre corporativo (Azure Key Vault) e sincronize via External Secrets Operator no namespace dynatrace:

kubectl create namespace dynatrace

kubectl -n dynatrace create secret generic dynakube \
  --from-literal="apiToken=${DT_OPERATOR_TOKEN}" \
  --from-literal="dataIngestToken=${DT_INGEST_TOKEN}"

2. Aplicação do Manifesto DynaKube (Cloud-Native Full-Stack)

Configure o manifesto garantindo coleta de métricas do Kubernetes API via ActiveGate e injeção seletiva nos namespaces de negócio:

apiVersion: dynatrace.com/v1beta2
kind: DynaKube
metadata:
  name: aks-split-bra-prd
  namespace: dynatrace
spec:
  apiUrl: https://<tenant-id>.live.dynatrace.com/api
  oneAgent:
    cloudNativeFullStack:
      tolerations:
        - effect: NoSchedule
          key: kubernetes.io/arch
          value: amd64
  activeGate:
    capabilities:
      - kubernetes-monitoring
      - routing
      - metrics-ingest

3. Checklist de Validação Pós-Onboarding

  • ✓ Todos os pods dynakube-oneagent e dynakube-activegate em status Running (1/1).
  • ✓ Cluster visível no menu Kubernetes Workloads do Dynatrace com eventos e métricas de CFS Throttling ativos.
  • ✓ Tags obrigatórias dt.owner, dt.costcenter e dt.tier propagadas automaticamente a partir das labels dos Deployments.
  • ✓ Alerting Profile vinculado ao canal de plantão SRE (PagerDuty / Microsoft Teams).
